## Visual QA loop

Screenshots live in `qa/screenshots/` (about 30 JPEGs at device scale 1, regenerated by `npm run qa:shots` plus the Chromium immersive tests). Each round: capture -> inspect -> fix code -> capture again. Findings from this round:

| Finding | Fix |
| --- | --- |
| The boot log and the desktop appeared as full-screen HTML while the camera was still travelling towards the monitor. | The boot is drawn onto the monitor texture on the shared boot clock; the camera reports when it has settled and the HTML OS (panel, icons, status) is gated on that. A probe sampling the DOM every 200 ms after Power on shows lock -> boot (painted) -> desktop with the gate opening only after arrival. |
| In headless Chromium (software rendering, low fps) the camera took twice as long to settle because the damping step was capped at 50 ms. | The cap is 100 ms, so slow devices arrive on time without overshoot. |
| Desktop icons showed through the 96%-opaque window body. | Windows are 98.5% opaque and the icons dim to 55% while a window is open. |
| The `Empty trash` button loses focus when it is disabled, so Escape stopped closing the Trash. | The Trash listens for Escape on the window while open. |
| The projects folder rendered rows as links with `role="listitem"`, which hides the link role. | Rows are real `<li>` elements wrapping the link. |

Final state reviewed at 390x844, 768x1024, 1280x720 and 1440x900: lock screen (3D room and CSS wallpaper), boot on the monitor, desktop (Immersive and Explorer), the desk view, Home (Files), Profile, Capabilities, Projects, a project window, Toolchain, Telemetry, Mail. Targets from the brief (90 / 95 / 95 / 95 on mobile) are met on every audited route. The lock screen now paints only Inter above the fold (the small status line used the mono face before, and the second font file on slow 4G pushed the simulated LCP to 5 s). Against localhost the simulated LCP flips between 1.1 s and about 5.5 s from run to run with identical observed paints (about 0.4 s): with no network latency the script chunks arrive at 20 ms and sometimes start hydrating a few milliseconds before the first paint, so the Lantern estimate folds the whole script graph into the LCP. Inlining the stylesheet (`experimental.inlineCss`) did not change the odds and quadrupled the HTML, so it was reverted. Over a real network the paint always lands first, which is why the live deployment is what is measured and reported, as the median of three runs.

### What keeps the numbers there

1. Phones default to Explorer mode, so three.js (about 240 KB gzipped) is never on the first-load path on small screens; the panel toggle opts in and the choice is remembered.
2. No WebGL capability probe at start-up; the scene reports failure through an error boundary instead.
3. CSS-only UI motion, no animation library; window entrances never start from `opacity: 0`, and the OS gate only applies after a boot or a camera move, never on a deep link.
4. The 3D room drops to a 4 to 8 fps demand loop while a window is open; the painted screens redraw at 2 to 14 fps depending on what they show.

## Accessibility notes

- Contrast: all text tokens on window surfaces are >= 4.5:1 except `dust` (hints), which is kept at 12 px+ and never used for essential information.
- Focus is always visible (2 px blue outline). Tab order follows the visual order; the desktop supports arrow keys; the applications menu is a `menu` with `menuitem`s; the Trash is a `dialog`.
- All motion is CSS and collapses under `prefers-reduced-motion`; the boot sequence is skippable and absent in Explorer mode.
- Screen-reader users get the app name next to each file ("profile.md (Text Editor)"), `sr-only` "Previous/Next destination" prefixes, live regions for the desk hint, the panel's window title, the inspect card and copied-address state, and `aria-current` on icons and the panel.
- WebKit note: Safari does not move keyboard focus onto links by default; the skip link test focuses it directly there and asserts the behaviour.

## Security review

- The only cross-origin request at runtime is the avatar image from `avatars.githubusercontent.com` (allowed in `img-src`, `referrerpolicy=no-referrer`, falls back to the build-time copy). No cookies, no analytics, no third-party scripts or fonts at runtime.
- `_headers` sets CSP (`default-src 'self'`, inline scripts/styles allowed only because static export has no nonces), `X-Frame-Options: DENY`, `nosniff`, referrer and permissions policies.
- External links hardened (`target="_blank" rel="noopener noreferrer"`), verified by test.
- `verify-export.mjs` scans the output for GitHub, Anthropic and AWS token patterns on every build.
- Dependencies: `npm audit` reported 0 vulnerabilities at install time.
